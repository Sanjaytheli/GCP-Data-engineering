Spark ==> inmemory (data processing)

==> Apache spark provide two main abstractions for working with distributed data 
	a) RDD  (older approach)
	b) Dataframe (newer approach)
	
Spark Framework:
---------------
Read data from text file (1L) (From the Harddisk) [LFS & HDFS & GCS] ==> Filter1 (50K) ==> write result into inmemory ==> Read data from inmemory ==> Filter2 (25K) ==> write result into inmemory ==> Read data from inmemory ==> Grouping ==> write result into inmemory ==> Read data from inmemory ==> summing operation ==> Final result ==> write this final result into our harddisk 

Read data from text file (1L) (From the Harddisk) [LFS & HDFS & GCS] ==> Filter1 (50K) ==> write result into inmemory ==> Read data from RDD/Dataframe ==> Filter2 (25K) ==> write result into inmemory ==> Read data from RDD/Dataframe ==> Grouping ==> write result into inmemory ==> Read data from Rdd/Dataframe ==> summing operation ==> Final result ==> write this final result into our harddisk 

what is RDD? [Resilient Distributed Dataset]
- IN pyspark, RDD is a fundamental data structure which is used for distributed data processing
- RDD are designed to be immutable, distributed collection of data that can be process in parallel across cluster of nodes

==> immutable: Rdd are read-only, which means we can not change content of RDD once it is created. We can create a new RDD by using existing RDD. We can create RDD when we are performing our data read operations and also we can create RDD when we are applying our transformations.

while applying transformation source is RDD, what is our target is RDD

spark ==> reading data from a text file  (LFS/HDFS/GCS..) ==> RDD1 (1L)
RDD1 ==> Filter1 operations (50K) ==> RDD2
RDD2 ==> Filter2 operations (25K) ==> RDD3

Note: in above statement just we can replace RDD with dataframe

==> Distributed: RDDS are distribute across multiple nodes in a cluster, and it allows for parallel processing on top of our data.

storage: parallel 
processing: parallel

==> RDDs can represent both structured and unstructured data 
==> RDDs can support transformations and actions 
==> RDD are laziness 
==> RDDS are required low level coding , low level APIs (application programming interface)
==> Error detection and debugging are kind of challenges as part of using RDDs

To simplify our coding + to take care of error detection and debugging operations in easy manner "DATAFRAMES" are introduced.

what is dataframe?

==> Dataframes are distributed data collections which are arranged into rows and columns in pyspark.
==> Dataframes are comparable to relations database tables
==> Dataframes are going to have column names and datatypes

==> Dataframe is a higher level abstraction which is built on top of RDD
==> while using dataframes we can able to use high level apis, bcz of that reason we can simplify the code
==> dataframes perfectly suitable when you are dealing with structured data 
==> on top dataframes also we can able to apply transformations and actions
==> dataframes provide high level apis with operations similar to those found in sql side

table ==> filter ==> where 
table ==> sorting ==> order by 
==> dataframes leverage spark catalyst optimizer and Tungsten execution engine, bcz of this reason dataframes are providing optimization for query execution/code execution


while applying transformation source is Dataframe, what is our target is Dataframe

spark ==> reading data from a text file  (LFS/HDFS/GCS..) ==> Dataframe1 (1L)
Dataframe1 ==> Filter1 operations (50K) ==> Dataframe2
Dataframe2 ==> Filter2 operations (25K) ==> Dataframe3

==> once dataframes are created we can not able to modify the data in that dataframe (immutable)

1. spark context 
2. spark session

1. spark context : this is primary responsible for coordinating and managing spark application, including resource allocation and task scheduling 
2. spark session: this is an entry point for structured data processing, by using this we can able to high level apis


1. spark context : If you want to deal with RDD first we need to create spark context component
2. spark session : If you want to deal with dataframe first we need to create spark session component
