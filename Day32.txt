Types of tables in bigquery 

1. Native tables / Managed tables / Internal tables: While dealing with bigquery tables if you are having dependency on "bigquery storage" such kind of tables we can call it as Native tables.

created tables ==> Loading data into this table ==> Bigquery storage [Native tables]
created tables ==> Loading data into this table ==> data retrieval operation ==> Bigquery storage [Native tables]


2. External tables: While dealing with bigquery tables if you are having dependency on "External services" such kind of tables we can call it as External tables.

External services: GCS , Aws S3, Azure blob storage, Google Drive

created tables ==> Loading data into this table ==> External services [External tables]
created tables ==> Loading data into this table ==> data retrieval operation ==> External services [External tables]


As part of external tables ==> your table will point to external service 

==> whole creation of the table we need to specify what type of table you want to use as per your requirement/usecase.

empty ==> Native 
upload ==> Native 
drive ==> External 
GCS  ==> Native 
	 ==> External

Scneario2: IN your project your source team sending files to your bucket on daily basis, every day when I am sending the files we will not delete previous day files.

Day1:
customer_20260806.csv 

Day2:
customer_20260806.csv 
customer_20260807.csv 

Day3: 
customer_20260806.csv 
customer_20260807.csv 
customer_20260808.csv 

In this scenario what type of table we need to create ?? [Native table & External table] [Best approach - create it as external table]

If you are going to create it as Native table ==> this data will sit on bigquery storage ==> coming to day3 in how many places we are having same data [Bigquery storage + GCS bucket] ==> this we can call it as duplicate/redudant data ==> because of this reason we need to pay money for Bigquery storage + GCS service ==> because of this reason cost is going to increase in our project 

To avoid above cost ==> better we need to create our table as External table ==> Now your data will sit only on our gcs bucket (it is not going to use bigquery storage) ==> you will pay money for only gcs service from storage perspective

select * from Externaltable; [triggering it on day3 ==> we can see data for day1+day2+day3]
